# 三厨师 SharedKitchen · 纯 E3T（2,000 万参数）

三名 AI 在同一张厨房地图上协作完成订单。模型以随机参数开始，直接通过在线游戏训练，示范预热局数为 **0**。历史 Colab A100 实验共训练 **6,291,456 个联合环境步**。开发集选出的策略在 100 局独立正常开局中每局均获得 **400 分、出餐 20 份**。

| 正常开局留出测试，每局 300 步 | 实测结果 |
|---|---:|
| 每局平均累计得分 | 400.00 |
| 每局平均出餐数 | 20.00 |
| 逐局平均同步成功率 | 14.86% |
| 每局平均等待步数 | 66.46 |

一个联合环境步指三个厨师各选一个动作、厨房推进一次。测试包含 30,000 个联合环境步，累计 40,000 分、2,000 份出餐、6,646 个等待步。所有 2,000 份出餐都有三名厨师参与。公开的逐局记录可用于重算所有数字。[100 局逐局指标](results/holdout.json)

## 运行

从仓库检出 `yhw` 分支后，在仓库根目录执行以下命令。训练所用的 SharedKitchen 引擎已随目录固定到 `de37e08`，可以跳过 Git 子模块初始化。历史 Colab 使用 Python 3.13.16、PyTorch 2.14.1+cu130 和 A100 80 GB，CPU 验证使用 Python 3.10.21、PyTorch 2.9.1。

```sh
python -m pip install -r reproduction/e3t_20m/requirements.txt
python -m reproduction.e3t_20m smoke --device cpu
python -m reproduction.e3t_20m train --device cuda --workers 11 --out reproduction/e3t_20m/runs/seed42
```

训练命令负责创建两套网络与优化器、并行采样、参数更新、分段保存、开发集选型和最终留出评估。本地输出保存在 `reproduction/e3t_20m/runs/seed42/`。其中 `latest.pt` 保存模型、优化器、环境轨迹和随机数状态，`best.pt` 和 `selection.json` 记录开发集选出的模型与解码方式，`holdout.json` 保存最终逐局结果。中断后沿用相同训练配置和输出目录继续。单独复测本地生成的入选模型可使用 CPU。

```sh
python -m reproduction.e3t_20m train --device cuda --workers 11 --out reproduction/e3t_20m/runs/seed42 --resume
python -m reproduction.e3t_20m evaluate --device cpu --checkpoint reproduction/e3t_20m/runs/seed42/best.pt --out reproduction/e3t_20m/runs/seed42/reeval.json
```

`results/` 内的 JSON 和 CSV 来自已完成的纯 E3T 实验。模型权重与优化器状态由训练命令在本地生成。下文的计时对应历史硬件环境，新机器上可以用同一开发与留出协议对照结果。

若要跟读实现，可按一次更新的顺序读：[网络初始化与 PPO 优化](shared_large.py) → [并行采样、队友历史、GAE 和断点状态](shared_train.py) → [工位意图与寻路](shared_adapter.py) → [三厨师动作执行与事件奖励](shared_work.py)。

## 训练方法

算法采用 Yan 等发表于 NeurIPS 2023 的 E3T。核心做法是在线混合当前策略和随机策略来生成训练队友，并用历史记录预测队友接下来的动作。三厨师、工位动作、奖励塑形和下面的网络规模属于本项目对 SharedKitchen 的适配。[E3T 原论文](https://proceedings.neurips.cc/paper_files/paper/2023/hash/07a363fd2263091c2063998e0034999c-Abstract-Conference.html) · [固定的 SharedKitchen 引擎](https://github.com/rain-xhy/hucooked/commit/de37e0818c2e76311e105ab8689e5162bd84133f)

**观测与动作。** 固定布局下，每名厨师的原生观测有 866 个值。去掉 490 维常量地图编码、追加自身的 70 维厨师状态后得到 446 维。适配器还将自己开局所在的三个官方出生格编码成独热向量，写入三个恒定的玩家激活位。策略在 14 个意图中选择，包括等待、让路、取主料、取配料、取盘、锅的西侧或东侧、切配、组装台的西侧或东侧、送餐，以及三种提前就位动作。动作掩码根据手持物、工位状态和占位限制可选意图。导航器负责寻路、避开已占用或已预留的格子，并执行一个原生移动、等待或互动动作。策略每个游戏步都能重新选择意图。适配器只调用引擎的单步寻路函数，三个厨师的工位意图均由网络选择。

**一次训练更新。** 三名厨师共享参数。每个并行环境按回合轮换一名学习者，另两名厨师为在线生成的队友。

1. 队友预测器读取学习者当前观测及最近 5 步历史。每条历史包含当时的观测、两个队友实际选过的工位意图独热向量和一个有效位。预测器为两个队友各输出一组 14 类意图概率。学习者将这 28 个概率与当前观测一起输入动作/价值网络。
2. 学习者从带温度的掩码策略采样。两个队友复用该网络，条件输入来自对随机高斯向量做 softmax 得到的分布。队友的采样概率为 $p=(1-\epsilon)\,\pi_T+\epsilon U$，其中 $\pi_T$ 是温度为 $T$ 的网络策略，$U$ 是该厨师当前可选意图上的均匀分布。
3. 将三个意图送入厨房，记录团队奖励、学习者的旧动作概率，以及两个队友实际选择的意图。用 GAE 计算优势并标准化。PPO 使用概率比 $r=\pi_{\mathrm{new}}(a)/\pi_{\mathrm{old}}(a)$，最大化 $\min(rA,\operatorname{clip}(r,0.88,1.12)A)$。动作/价值网络同时优化系数为 0.5 的 Smooth L1 价值损失与熵奖励，预测器用实际队友意图的分类交叉熵更新。两个网络分别使用 Adam。
4. 正式评估时，三名厨师各自维护历史，用学习所得的队友预测和同一套策略行动。训练队友的随机混合只用于采样训练局。

**参数与超参数。** 动作/价值网络有 19,005,455 个参数。它接收 474 维输入，主干宽度为 1,024，包含 4 个残差块，各块前馈层宽度为 2,240、使用 SiLU 和 LayerNorm。队友预测器有 994,552 个参数，采用 256 维输入投影、256 维 GRU 及 652 维预测头。可训练参数合计 **20,000,007**。

| 项目 | 正式训练配置 |
|---|---|
| 随机种子、并行环境、采样长度 | 42，64 个环境，每次各采样 64 步，每批 4,096 个环境步 |
| PPO 更新 | 每批最多 3 个 epoch，minibatch 512，平均近似 KL 超过 0.025 时提前结束该批的后续 epoch |
| 优化与优势估计 | 两个 Adam 学习率均为 0.00012，Adam epsilon 为 0.00001，梯度范数上限 0.7，折扣 0.99，GAE λ 为 0.97 |
| 探索退火 | 前 2,000,000 环境步线性调整，基础温度 1.25 → 0.9，队友随机混合 ε 为 0.16 → 0.025，熵系数 0.025 → 0.006，之后维持终值 |
| 每回合的探索差异 | 按环境编号和回合轮换四组。学习者温度倍率依次为 0.85、0.95、1.05、1.15，队友温度倍率为 0.7、0.9、1.1、1.35，队友 ε 倍率为 0.4、0.8、1.2、1.6 |

**奖励。** 原生环境每成功送出一份成餐得 20 分。训练前期对生产进度额外给奖励，同一步的事件奖励相加。主料入锅 +0.75，配料放上切配台 +0.5，每次切配 +0.1，食材放上组装台 +0.5，完成组装 +1，普通主菜出锅 +1，协作主菜出锅 +2。计算优势时使用的奖励为

$$
r_{\mathrm{train}}=0.05\left(r_{\mathrm{game}}+\max\left(0,1-\frac{n}{2{,}000{,}000}\right) r_{\mathrm{events}}\right),
$$

其中 $n$ 是已采样的联合环境步。训练到 200 万步后，剩余更新只使用缩放后的游戏奖励。评估各局成绩直接读取环境终局的 `info["metrics"]`。

## 选模与结果解释

训练先试跑 32,768 步，随后分段到 1,572,864、3,145,728、4,718,592 和 6,291,456 步。每 196,608 步进行一次固定种子开发评估，另记录随机初始化、第一次 PPO 更新和试跑结束时的结果。每次在相同 32 局（种子 918401–918432）上比较温度 1.0 采样、温度 0.65 采样和贪心取最大概率三种模式。选择平均原生得分最高的检查点与模式，同分保留较早检查点。[35 次开发评估](results/development.csv) · [选型记录](results/selection.json)

- 开发均分在随机初始化时为 0，在 786,432 步时为 295.00，在 **2,752,512 步**首次达到 **400.00**，当时入选的模式为贪心。训练结束时开发均分也为 400.00。比较断点使用的是得分，同分断点的同步率和等待步数可以不同。
- 冻结选定策略后，用独立种子 **928401–928500** 各跑一局 300 步的正常开局，每局 10 份普通餐和 10 份协作餐。表首的同步成功率按局计算，再跨局取均值。若合并所有局的同步次数与尝试步数，则为 1,000 / 6,748 = **14.82%**。原生等待步数为协作出锅就绪步数减同步成功次数。
- 纯分支共完成 **1,536 次 PPO 更新**。历史训练硬件为 NVIDIA A100-SXM4 80 GB，使用 11 个环境工作进程。首条随机初始化日志至最后开发评估约 **41 分 43 秒**。用本目录的评估入口在 CPU 上重测选定模型，100 局完整 JSON 与历史 A100 记录逐字节一致，SHA-256 为 `6156c0a67979598b704a4ec69b89ea2f5841a22309dc8840ed54c5ae44d60046`。
- 测试范围是这张固定地图上三名共享策略 AI 的配合，包含官方出生格的角色排列。与人类、新策略或其他厨房布局的协作需要单独评估。
