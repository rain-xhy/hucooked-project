每局平均出餐 **19.00** 单，团队得分 **380.00**，同步成功率 **21.74%**，等待 **45.00** 步。

## 模型与训练设置

- 从随机权重开始，示范数为 0。CPU，种子 488。Manager 为 115→128→128→12（32,908 参数），Worker 为 149→128→128→6（36,486），Critic 为 112→128→128→1（31,105）。隐藏层 Tanh，执行参数 69,394，检查点共 100,499 个参数。首阶段另训练临时 Worker Critic。
- 入榜权重的来源依次为 Worker 技能 PPO 36 轮、Manager PPO 30 轮、联合 PPO 72 轮、冻结 Worker 后的 Manager PPO 6 轮。每轮 12 路 × 128 步，合计 144 轮、221,184 个环境步。各阶段重新建环境，每路按 300 步结算；按四阶段分别取整，实际走完 180 + 144 + 360 + 24 = 708 局，另有部分回合。
- Worker 按技能完成与接近目标获得奖励，Manager 初训用出餐奖励，联合及最后的 Manager 阶段使用工序进度塑形，最后阶段加入等待成本。学习率依次为 0.0005、0.00035、0.0002、0.00032。PPO 每批 4 个 epoch，minibatch 1,024。
- 原始三次运行的预算分别为 36+36、72、84 轮；第二段接第一段选中权重，第三段接第二段末权重。按传入下阶段或最终入榜的检查点验证时刻相加为 283.37 秒（100.69 + 165.18 + 17.50，含阶段内验证）；原始三个作业全部跑完、含末尾评估共 511.96 秒。以上均为阶段耗时之和。
- 训练入口为 leaderboard 下的 `v2/pure_rl.py`。三段原始配置和进展在 `evidence/` 中，使用原命令复跑时按顺序将 resume 指向新运行生成的输出目录。
